# Certification record

Human-reviewed record for the Clojure -> Python math cutover (P-022). This file
is PUBLIC. It records only the pinned identifiers and the coverage obligations;
it never records a zid, report id, participant id, precise private timeline,
vote row, blob or error dump.

An untrusted job must not commit to this file. A maintainer reviews and commits
it.

## What a release certificate is

The certificate is the tuple:

> candidate commit/image + Clojure oracle commit/image + **fixture bundle pin** +
> schedule/policy hashes + runner/configuration + complete evidence.

A different candidate, numerical dependency, polarity setting, schedule or
deployment configuration invalidates the affected evidence.

## Fixture bundle pin (P-022 section A)

The private fixture bundle lives at `s3://polis-certification-data/<bundle-id>/`
and is described by `polismath.replay.fixture_bundle`. Only the facts below may
be published; everything else about the bundle is private.

Regenerate the block mechanically — never hand-edit it:

```bash
cd delphi
uv run python scripts/certify_data.py pull \
    --bundle-id <bundle-id> --dest /tmp/bundle
uv run python scripts/certify_data.py pin \
    --manifest /tmp/bundle/manifest.json
```

`certify_data.py pin` is limited by construction to the keys in
`fixture_bundle.PUBLIC_PIN_KEYS`; `tests/test_certify_bundle.py` and
`tests/test_certify_bundle_integration.py` assert that a planted synthetic zid,
uid, topic or comment body never reaches its output. Measured metrics are also
withheld: a `(V, U, P, C)` tuple can fingerprint a conversation.

### Selection and reproducibility rules

- Selection uses only the committed numeric metrics in
  `delphi/scripts/certify_datasets.json` — never a topic or any text. Every
  ordering ends with the zid-ascending tie-break, applied inside the private
  selection process.
- If a rule has no candidate at its rank, bundle construction FAILS naming the
  missing role. It never silently picks a smaller case, skips the role, or
  reuses an older result. A threshold or rank change requires a reviewed config
  edit and a new bundle version.
- The `pc-v1-dense*` roles alone may fall back to a deterministic synthetic
  stress case (`gen-v1-dense-stress`), and only under an explicitly recorded
  approval (`--accept-synthetic`), which the manifest stores.
- Survey and extraction run inside ONE read-only repeatable-read transaction (or
  against a clone with all writers disabled). The manifest records which.
- The bundle carries a lossless private event stream with integer-millisecond
  timestamps and explicit ordinals. **Ordering guarantee:** the polis `votes`
  table has no primary key, no unique index and no identity/serial column, so
  there is no portable event identity. The extract order (`created ASC,
  ctid ASC`) is FROZEN into the bundle bytes and is authoritative for every
  replay; re-restoring the snapshot need not reproduce ctid order. Ambiguous
  equal-time opposite votes are COUNTED in the manifest's census and are never
  given an invented historical order — they need their own specified contract.
- Moderation timelines woven from a comments snapshot are SYNTHESIZED by
  deterministic rule and are labelled as such. A comments snapshot is current
  state and a latest-modification time, not a history of every moderation
  action.

### Immutability and access

- The publisher REFUSES to republish a bundle id whose objects would differ in
  bytes. S3 versioning alone does not make a logical bundle immutable.
- Every object is pinned by version id in `<bundle-id>/pins.json`, written last.
  `pull` verifies every hash against both the manifest and the pins before any
  engine may read the data, and rejects path traversal, absolute paths and
  symlinks.
- The role -> zid mapping lives in a SEPARATE restricted object
  (`<bundle-id>/provenance.json`). Ordinary certification runs do not read it;
  `pull` fetches it only with `--with-provenance`.
- A dedicated writer publishes. Test readers get `s3:GetObject` /
  `s3:GetObjectVersion` only, so a reader cannot overwrite or delete a bundle.
- The bundle is retained for the supported lifetime of the certificate.
  Retirement requires an explicit privacy-approved decision, not a short
  artifact TTL.
