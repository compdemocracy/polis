# Job-view checks

After installing locked dependencies in server and client-report, run `npm --prefix client-report run test:jobviews`. CI calls the same entry point. No NODE_PATH is required; Babel and TypeScript transforms resolve from their own packages, and all React imports use client-report's instance even when alpha has its own installation.

The default client-report Jest job excludes only the jobViews.* characterization suites; their dedicated job executes them. Other report tests remain in the default suite. The recordings use 12 generated states through real report components and alpha Agenda/hierarchy code. Charts, comment-list leaves, auth and network are controlled adapters; no provider call occurs. While TopicPage still requests paid generation, real consensus eligibility decides whether it sends that POST, whose endpoint/body/token argument are recorded alongside GET order. Recorded narratives/statements are supplied, including an old-statement ordering case, two-job same-day group and a partial analysis with images.

Record twice on unchanged source/input hashes with `RECORD_JOB_VIEWS=baseline npm --prefix client-report run test:jobviews` and compare the golden. Do not record on changed views. Expected differences live in jobViews.expected-differences.json; each names state/view, exact before/after, reason and ruled:<reference>. Pending or free-form rulings fail. Product views cannot change alongside source corpus, helpers or recording/comparison rules. A re-record must leave expected differences empty. The ruling format comes from the vote-path module.

The mutation runner restores each modified product source in a finally block. It requires a failed recorded-value assertion, not just a nonzero Jest exit. Nine non-equivalent mutations are expected to fail. None targets TopicPage's paid generation request (its payload, eligibility check or token argument): the topic page is moving to stored statements only, which removes that request, so those anchors would not survive it. The recordings still capture the request while it exists. The legacy section-reduce comparator is equivalent on the corpus because run.created_at is absent, so it is documented and excluded rather than counted as killed.

Provenance helpers, if installed, have their own independent `sh server/characterization/jobviews/check-provenance.sh` entry point. They are not required by the baseline recording lift. A view's enabled-mode observation can be captured with JOB_VIEWS_OBSERVE for review; this bypasses comparison only to export observations and is never an acceptance verdict. Do not use it in CI. Subsequent replay requires ruled exact differences.
